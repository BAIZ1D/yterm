# Contributing to yterm

First off, thank you for considering contributing to yterm! It's people like you that make yterm such a great tool.

## How Can I Contribute?

### Reporting Bugs
* Check the [Issues](https://github.com/BAIZ1D/yterm/issues) to see if the bug has already been reported.
* If not, open a new issue. Include as much detail as possible, such as your OS, shell, and the exact command that failed.

### Suggesting Enhancements
* Open an issue to discuss the enhancement before writing code.
* Explain why this change would be useful to other users.

### Pull Requests
1. Fork the repo and create your branch from `main`.
2. If you've added code that should be tested, add tests.
3. Ensure the script still works on macOS, Linux, and WSL.
4. Open a Pull Request!

## Style Guide
* Keep it simple. yterm is a "glue script."
* Avoid heavy dependencies. If it can be done in Bash, do it in Bash.
* Use `command curl` instead of just `curl` to avoid issues with user aliases/shims.
